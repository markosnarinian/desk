---
title: Scratch experiments
description: Use scratch workspaces for quick tests, throwaway scripts, and anything you would otherwise put in /tmp.
---

## Start an Experiment

```sh
desk scratch json-parser
```

The name is optional. Without one, the workspace is called `scratch`. Use names that will make sense in `desk list` a month from now.

Inside the workspace, use your usual tools:

```sh
npm init -y
npm install some-library
node try.js
exit
```

<Callout type="tip">
Prefer a scratch workspace over `/tmp` for anything you might want to come back to. The operating system can clear temporary directories at any time, without any of desk's checks.
</Callout>

## Create Without Entering

Use `--no-enter` to create a workspace from a script or another tool. The ID is the only output:

```sh
id=$(desk scratch notes --no-enter)
desk enter "$id"
```

## Come Back Later

```sh
desk list
desk enter ID
```

Entering a workspace also clears its done flag, so you can change your mind after `desk done`.

## Keep the Good Ones

If an experiment turns into something you want to keep, pin it so cleanup never considers it:

```sh
desk keep ID
```

For anything long-lived, consider moving it out of desk into a normal project directory. `desk list` shows where it is.

## Clean Up

A scratch workspace is eligible for cleanup only when it is empty. If you are finished with an experiment, delete its files yourself, then mark it done:

```sh
desk enter ID
# remove the files you no longer need, then exit
desk done ID
desk gc
```

See the [cleanup lifecycle](/docs/cleanup-lifecycle/) for the full process.
