## Restore a Quarantined Workspace

Quarantined workspaces show the state `quarantined` in `desk list`. Restore one with:

```sh
desk restore ID
```

```text
restored 702378b08f9e
```

The workspace moves back to managed storage, its done flag is cleared, and any pin is kept. You can enter it right away.

<Callout type="tip">
desk refuses to enter or reopen a quarantined workspace. If `desk enter` or `desk open` reports that a workspace is quarantined, restore it first.
</Callout>

## Find a Workspace

`desk list` shows every workspace with its full path, so you can always reach the files directly, even without desk:

```sh
desk list
```

If you remember the repository but not the ID, `desk open` with the same source returns the existing workspace.

## Lost Workspaces After Changing DESK_HOME

Each data root has its own registry. If workspaces seem to have disappeared, check whether `DESK_HOME` is set differently in the current shell:

```sh
echo "${DESK_HOME:-default root}"
```

Changing the variable never moves or deletes workspaces. Set it back to see them again.

Earlier versions of desk stored workspaces in platform-specific locations rather than `~/.desk`. If you used one of them, see [Existing Installations](/docs/configuration/#existing-installations).

## Interrupted Operations

The registry is replaced atomically and desk works out each workspace's location from the directory that actually exists. A quarantine or restore that was interrupted after the rename is therefore visible in `desk list` and can be completed or undone with the usual commands.

If `desk list` reports `workspace directory missing; registry retained`, the directory was removed outside desk. desk keeps the registry entry so you notice; it cannot recreate the files.

## After a Purge

Purging is permanent. desk cannot restore a purged workspace. For a repository, clone it again from origin; anything that was only local is gone.
