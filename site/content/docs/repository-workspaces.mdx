title: Repository workspaces
description: Clone a repository or return to an existing workspace without naming a task first.

## Choose a source

```sh
desk new owner/repo                             # GitHub shorthand
desk new https://gitlab.com/group/project.git    # any Git URL
desk new git@github.com:owner/repo.git            # SSH
desk new ../my-project                          # local source
```

Local paths must start with `/`, `./`, or `../`. desk runs your installed Git with your usual credentials, creates an independent clone, and enters it with [shell integration](/docs/shell-integration/). If cloning fails, it removes the new workspace and reports Git's error.

## Choose a workspace

By default, `desk new REPOSITORY` offers existing workspaces alongside a new clone.

| Flag | Effect |
| --- | --- |
| `--fresh` | Create another independent clone. |
| `--reuse` | Reuse the most recently used workspace, or create one. Remember this preference for the repository. |
| `--choose` | Show the chooser once, without changing a remembered preference. |

Use one flag at a time. Returning to a clone never fetches, pulls, or resets it; update it yourself with Git. Use `desk switch NAME` when you already know the workspace.

## How sources match

desk reads each workspace's Git `origin` and compares host and path, ignoring scheme, user, and a trailing `.git`. GitHub paths are case-insensitive, so these identify the same source:

```text
octocat/Hello-World
https://github.com/octocat/hello-world
git@github.com:octocat/Hello-World.git
```

When you're done, use [cleanup](/docs/cleanup/) for safety-checked removal, or `desk rm` to remove a workspace explicitly after confirmation.
