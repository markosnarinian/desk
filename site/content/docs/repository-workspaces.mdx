## Clone a Repository

`desk new` accepts several forms of repository:

<Tabs>
<Tab title="GitHub shorthand">

```sh
desk new octocat/Hello-World
```

`owner/repo` is expanded to `https://github.com/owner/repo.git`.

</Tab>
<Tab title="URL">

```sh
desk new https://gitlab.com/group/project.git
desk new git@github.com:owner/repo.git
desk new ssh://git@example.com/repo.git
```

URLs are passed to Git as given.

</Tab>
<Tab title="Local path">

```sh
desk new ../my-project
```

Local paths must start with `/`, `./`, or `../`. They are converted to an absolute path.

</Tab>
</Tabs>

desk runs `git clone` into a new workspace and takes you there. Authentication uses your normal Git and SSH configuration.

## Return to It

Running `desk new` again with the same repository takes you back to the existing workspace instead of cloning a second copy, however you spell it:

```sh
desk new octocat/Hello-World
desk new https://github.com/octocat/hello-world
desk new git@github.com:octocat/Hello-World.git
```

desk compares each workspace's Git `origin` by host and path, ignoring the scheme, user, and a trailing `.git`. Path case is ignored on GitHub, where it doesn't matter.

desk does **not** fetch, pull, or reset when it returns to a clone. Update it yourself with Git. You can also use `desk cd NAME` directly.

## When a Clone Fails

If `git clone` fails, desk removes the new workspace and reports Git's error. Fix the problem, such as credentials or a typo, and run `desk new` again.

## Before Deleting

`desk rm` shows uncommitted changes and unpushed commits before asking, but deletes whatever you confirm. If you're unsure, check first:

```sh
git status --short
git log --branches --not --remotes
git stash list
```
