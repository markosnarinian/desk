## Why desk?

As agents take more programming work to the cloud, local work becomes more occasional and fragmented: a temporary clone to explore, a playground to test a library, a throwaway scaffold, a local prototype.

Agents get cloud machines they can spin up and tear down. desk gives humans a similar start and finish for local work: create a workspace, explore with your usual tools, return when needed, and remove it when you're done.

## When to use it

- **Build a playground.** Test a library, generate a throwaway scaffold, or prototype an idea in an empty workspace.
- **Explore a repository.** Clone it to read the code, debug, or try a change. Keep the workspace only as long as you need it.
- **Bring agent work home.** Copy an Amp task to edit locally, or follow it live to test as it changes. No push required.

```sh
desk new                  # start an experiment
desk new owner/repo       # choose a workspace or a new clone
desk list                 # see what you've kept
desk switch misty         # return by name or unique prefix
desk info                 # inspect the current workspace
desk amp                  # browse recent Amp tasks
desk finish               # mark a workspace disposable
desk cleanup              # preview eligible workspaces, then confirm
```

## What it does today

desk manages plain directories, not virtual machines or containers. It doesn't install dependencies or replicate services and secrets. [Amp sync](/docs/amp/) transfers code; you run the project's usual setup locally.

You decide when to run [cleanup](/docs/cleanup/). It only removes eligible, inactive workspaces with no local-only work, after confirmation. Removed workspaces stay in garbage for 72 hours; every desk invocation silently collects expired garbage. There is no daemon.

It runs on macOS and Linux, with zsh (including Oh My Zsh), bash, and fish integration. It's early; installation is from source. Licensed under GNU AGPL v3.
