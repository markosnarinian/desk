## Usage

```text title="Usage"
desk COMMAND [ARGUMENT]
```

| Command | Purpose |
| --- | --- |
| [`desk new [REPOSITORY]`](/commands/new/) | Create an empty workspace or a clone, and go there |
| [`desk cd [NAME]`](/commands/cd/) | Go to a workspace |
| [`desk path [NAME]`](/commands/path/) | Print a workspace's path |
| [`desk list`](/commands/list/) | Show workspaces; `*` marks the current one |
| [`desk rm [NAME]`](/commands/rm/) | Delete a workspace after confirmation |
| [`desk init SHELL`](/commands/init/) | Print shell integration for zsh, bash, or fish |
| [`desk version`](/commands/version/) | Print the version |

`desk help`, `desk --help`, or `desk` with no arguments prints a summary.

## Conventions

<ParamField name="NAME" type="name or prefix">
A workspace name such as `misty-ember`, or any prefix that matches only one workspace, such as `mis`. Leave it out to use the workspace containing your current directory.
</ParamField>
<ParamField name="REPOSITORY" type="owner/repo, URL, or path">
GitHub `owner/repo`, any Git URL, or a local path that starts with `/`, `./`, or `../`.
</ParamField>

`desk new` and `desk cd` change your directory only with [shell integration](/docs/shell-integration/). Without it, `desk new` still creates the workspace and prints its path.

## Output and Exit Status

Paths and listings go to standard output. Messages and prompts go to standard error, so `cd "$(desk new)"` works in scripts. Errors print with a `desk:` prefix and exit with status `1`:

```text
desk: no workspace "nope" (see desk list)
```
